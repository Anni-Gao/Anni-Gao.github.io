Build Your Own VPN Server from Scratch

Introduction

A VPN (Virtual Private Network) encrypts your internet traffic, masks your real IP address, and enables secure access to remote resources.

Compared with commercial VPN providers, running your own VPN server provides greater privacy, full control, and flexibility.

This tutorial demonstrates how to deploy a personal VPN server based on the following architecture:

VMess + WebSocket + TLS + Cloudflare CDN

1.Prerequisites

Before building your own VPN server, make sure you have the following resources ready:

1. A Virtual Private Server (VPS)

You can choose a VPS provider based on your location, budget, and performance requirements:

  • Recommended VPS provider: Oracle Cloud
  • Recommended Configuration:
    • CPU: 1 vCPU or above
    • Memory: 1 GB RAM or more
    • Operating System: Ubuntu 22.04 LTS / Debian 12
    • Bandwidth: Select based on your usage requirements

2. Connect to Your VPS via SSH

After creating your Oracle Cloud instance, you will receive:

  • Public IP address
  • SSH private key

When creating the instance, Oracle Cloud allows you to generate an SSH key pair or upload your own public key.

The private key must be kept securely because it is required for SSH authentication.

3. Domain Name

Purchase a domain and configure DNS records to point it to your VPS IP address.

  • Recommended domain registrar: Namecheap

Example: vpn.example.com

The domain will later be used for:

  • TLS certificateTLS
  • Cloudflare CDN
  • Client configuration

2. Configure Cloudflare and Xray

1. Configure Domain DNS Records

Add the following DNS record in Cloudflare:

Type Name Content Proxy Status
A vpn YOUR_SERVER_IP Proxied

Make sure Cloudflare CDN proxy is enabled, otherwise traffic will not pass through Cloudflare.

2. Configure Server Firewall Rules

Add the following inbound rules in your server security settings:

Source CIDR IP Protocol Destination Port Purpose
0.0.0.0/0 TCP 8443 Xray WebSocket + TLS
0.0.0.0/0 TCP 22 (SSH) SSH access

7. Common Maintenance Commands

The following commands can be used to manage and troubleshoot the Xray service.

Restart Xray systemctl restart xray
Enable Xray at boot systemctl enable xray

8. Troubleshooting

The following table covers some common issues you may encounter during deployment.

Problem Possible Cause Solution
Permission denied Incorrect certificate file permissions Check the certificate ownership and permissions. Use chown nobody:nogroup and appropriate chmod settings.
Connection refused Port 8443 is blocked Check your Oracle Cloud security rules and make sure TCP port 8443 is allowed.
Client cannot connect Incorrect Cloudflare SSL/TLS mode Set the Cloudflare encryption mode to Full (strict).
Invalid certificate Domain or SNI mismatch Make sure the SNI and certificate domain match.
Import failed Incorrect UUID or domain Verify the UUID, domain, port, and other configuration parameters.
Xray fails to start Invalid configuration Check the Xray logs with journalctl -u xray -f.
Port is not listening Xray service is not running Run systemctl status xray and restart the service if necessary.
